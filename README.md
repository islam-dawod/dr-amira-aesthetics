# Dr. Amira Dabbagha — Medical Aesthetics

אתר סטטי, עברית RTL, mobile-first.
**Natural. Precise. Personal.**

אין תלות בפריימוורק, אין build חובה, אין node_modules. HTML + CSS + Vanilla JS.
כל קובץ HTML הוא עומד־בעצמו וניתן להעלות את התיקייה כמו שהיא לכל אחסון סטטי.

---

## הרצה מקומית

```bash
python -m http.server 4321
```

ואז `http://localhost:4321`.

חשוב להריץ דרך שרת ולא לפתוח את הקובץ ב־`file://` — כלי ההדמיה קורא פיקסלים
מ־canvas, ודפדפנים חוסמים את זה על פרוטוקול file.

## The Amira AI Mirror™ — איך זה עובד

`assets/js/mirror.js`. **העיבוד מתבצע כולו בדפדפן.** אין `fetch`, אין העלאה,
אין ספק AI חיצוני, אין שמירה. התמונה יושבת ב־canvas ונמחקת ב־`pagehide`.

המסלול: **Upload → Align → Explore → Preview**

היישור (שלב 02) הוא הבסיס לכל השאר: המשתמשת ממקמת את הפנים בתוך מסגרת עם קווי
עזר לעיניים ולפה, ומכאן נגזרים מיקומי כל תשעת האזורים באופן פרופורציונלי.

המנוע עצמו הוא גיאומטרי־אופטי — displacement mapping עם דגימה בי־ליניארית,
ופלוס החלקה סלקטיבית מרוככת־שוליים לאזורי ההבעה. שתי משפחות אפקטים:

| סוג | אזורים | מה קורה |
|---|---|---|
| `soften` | מצח, בין הגבות, צדי העיניים | החלקה מקומית של תדרים גבוהים |
| `bulge` / `define` / `balance` | שפתיים, לחיים, סנטר, קו לסת | היסט גיאומטרי עדין |

**זה לא מודל חיזוי, וזה בכוונה.** מודל שמאומן על "תוצאות" מבטיח דבר שאי אפשר
להבטיח דרך מסך, ובנוסף היה מחייב שליחת תמונת פנים לשרת. הבחירה הזו מתועדת
בגלוי גם בפני המשתמשת ב־`ai-privacy.html` וגם במאמר ב־`articles.html#ai`.

העוצמות מוגבלות מלמעלה בכוונה (`LEVELS` ב־`mirror.js`) — פחות מ־2% מהפיקסלים
משתנים גם ב־Enhanced. אם מבקשים לחזק, זה הקבוע היחיד שצריך לגעת בו.

### ה־hand-off לייעוץ

לחיצה על *Discuss this look with Dr. Amira* שומרת ב־`sessionStorage` **רק**
שמות האזורים והרמה — לא את התמונה. `contact.html` קורא את זה, מסמן מראש את
האזורים בשאלון ומציג באנר. נבדק ועובד.

כל התמונות ב־`assets/img/` הן SVG ממלאי מקום. להחליף באותם שמות קבצים:

- `portrait-hero.svg` — דיוקן ראשי, יחס 4:5
- `portrait-about.svg` — דיוקן לעמוד ד״ר אמירה, 4:5

מטא־דאטה של הגלריה יושב ב־`assets/js/data.js` תחת `AMIRA_RESULTS` —
כותרת, טיפול, אזור, מספר מפגשים, מתי צולם והערה. יש לעדכן אותו יחד עם התמונות,
כולל `alt` מדויק לכל זוג.

> **תקן צילום.** אותה זווית, אותו גובה מצלמה, אותו אורך מוקד, אותו מרחק, אותה
> תאורה, אותו רקע, אותה הבעה, בלי שינוי איפור, בלי פילטר, בלי ריטוש.
> זוג שמשנה אחד מהמשתנים האלה אינו מציג תוצאה — הוא מציג תמונה אחרת.
> הכלל הזה מוצהר בפני המבקרת ב־`results.html`, ולכן הוא מחייב.

## חיבור הטופס ל־CRM

`contact.html` עובד היום בלי backend: השאלון בונה הודעת WhatsApp מסודרת עם כל
התשובות. זה fallback מכוון — בקשה לא נעלמת בשקט.

לחיבור CRM אמיתי: להגדיר `action` על `<form id="consultForm">` (יש הערה במקום).
השדה המוסתר `#flowContext` נושא את התשובות כטקסט מובנה. ברגע שיש `action`,
הטופס מבצע POST רגיל במקום לפתוח WhatsApp.

## נגישות

נבנה מול WCAG 2.2 רמה AA. נבדק על **19 עמודים × 3 רחבים (375 / 768 / 1280)**:

- **ניגודיות — 0 כשלים.** נמדד על הצבע המחושב בפועל של כל צומת טקסט מול הרקע
  הצבוע בפועל, כולל שקיפויות.
- **גודל יעדי מגע (2.5.8) — 0 כשלים** מחוץ לחריג "קישור בתוך משפט".
- **אין גלילה אופקית** באף עמוד ובאף רוחב.
- ניווט מלא במקלדת, כולל מחוון ההשוואה (`input type=range` אמיתי), התפריט
  והחלוניות. Escape סוגר, והמיקוד חוזר לנקודת הפתיחה. נבדק.
- `prefers-reduced-motion` מבטל בפועל את כל האנימציות.

### הדבר החשוב לדעת על הפלטה

הפסטלים של האפיון יוצרים ניגודיות חלשה בקלות. לכן ב־`main.css`:

```

--taupe-text  #665750   כל תווית/eyebrow/kicker. 4.8:1 על rose, 6.3:1 על ivory.
--ink-muted   #645954   טקסט גוף משני. 4.7:1 על rose.
```

הגרסה הראשונה השתמשה ב־`--taupe` לתוויות והגיעה ל־2.47:1 — כשל ממשי שנתפס

בנוסף: `.section--plum` מגדיר מחדש **כל** גוון מרוכך, כי צבע שנועד לרקע בהיר

## `_build/` — כלי עזר, לא תלות

שבעת עמודי הטיפולים וארבעת עמודי המדיניות זהים במבנה, ולכן הם מיוצרים מתבנית.
**ה־HTML שנוצר עומד בעצמו** — אפשר להתעלם מ־`_build` לחלוטין ולערוך את קבצי
ה־HTML ישירות.

לעריכת התוכן דרך התבנית:

```bash
powershell -File _build\build-treatments.ps1
powershell -File _build\build-policies.ps1
```

התוכן ב־`treatments.json` / `policies.json`, המסגרת ב־`*.template.html`.
הסקריפטים עצמם ASCII בלבד ומקבלים UTF-8 מהחוץ — כך PowerShell 5.1 לא מקלקל עברית.

> **אזהרה:** הרצת סקריפט דורסת את קבצי היעד. אם ערכת `treatments/lips.html`
> ידנית — או שתעדכני גם את ה־JSON, או שלא תריצי.

### קישור תצוגה מקדימה בקובץ אחד

```bash
node _build/bundle-single-file.js
```

מייצר `_build/amira-site.bundle.html` — כל 19 העמודים בקובץ אחד עומד בעצמו,
כולל הגופנים מוטמעים כ־data URI והתמונות מוטמעות. נוח לשליחה לסקירה בלי שרת
ובלי clone. הפלט הזה ב־gitignore כי הוא תוצר build.

הקובץ הוא **תצוגה מקדימה, לא הגרסה שעולה לאוויר.** מה שנפרס הוא האתר
מרובה־הקבצים. שלושה דברים שונים בחבילה:

1. הגופנים מוטמעים (במקום Google Fonts) — כך היא עובדת גם בסביבה שחוסמת CDN.
2. הפלט הוא ASCII בלבד, כך שאינו תלוי בהצהרת charset חיצונית.
3. הניווט הוא router שמרנדר מחדש את כל גוף העמוד ומריץ מחדש את הסקריפטים,
   כדי שלא יישארו listeners של עמוד קודם.

> **למי שיערוך את הבנדלר:** ההזרקה של התוכן נעשית עם function replacers ולא
> עם מחרוזות. `String.replace` מפרש `$$` / `$&` / `$'` בתוך מחרוזת ההחלפה
> כתבניות — ו־`$$` שמצטמק ל־`$` שינה בשקט את `var $$ = ...` ב־`site.js`
> ל־`var $ = ...`, כך שכל חיפוש של אלמנט בודד החזיר מערך.

## החלטות תוכן שכדאי לשמר

האתר מנוסח לפי כלל אחד: **הוא לא קובע למטופלת שהיא צריכה טיפול, ולא נוקב בכמות.**

- אזור בפנים נפתח בשאלה "רוצה לראות הדמיה אפשרית באזור הזה?" — לא באמירה
  "את צריכה כאן חומר מילוי".
- תרחישי `0.5 ml` / `1 ml` מסומנים כתרחיש המחשה, לא כהמלצה ולא כהבטחה למראה.
- כל עמוד טיפול כולל סיכונים ותופעות לוואי, כולל הנדירות והחמורות.
- ההבהרה על ההדמיה מופיעה כשער חובה לפני יצירתה, על התמונה עצמה
  (`AI PREVIEW · FOR ILLUSTRATION ONLY`), מתחתיה, בעמוד — וגם נצרבת לתוך
  קובץ ההורדה, כדי שההדמיה לא תיסע לשום מקום בלי ההקשר שלה.
- "ולעיתים ההמלצה היא לא לטפל" חוזר בכל עמוד. זה עמוד השדרה של המיתוג.

אם עורכים טקסטים — לשמר את הכלל הזה. הוא גם עמדה מקצועית וגם הגנה: טענות
בתחום האסתטיקה חייבות להיות נכונות ולא מטעות.
